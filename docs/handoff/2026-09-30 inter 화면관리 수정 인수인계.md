## 0. 먼저 알아 둘 것

### 0-1. 실제 쇼핑몰에 올리는 방법 (스마트디자인 편집기 API)

관리자 로그인 후 `https://<몰>.cafe24.com/disp/admin/editor/main?skin_no=1` 을 열고, 그 창 콘솔에서 파일을 **부분 치환**한다.
파일 전체를 덮어쓰지 않는다 — **서버본은 로컬과 다르다** (아래 0-2).

```js
// 편집기 창에서 실행. pairs = [[찾을 문자열, 바꿀 문자열], …]. 찾을 문자열이 정확히 1번 나와야 저장한다.
window.__patch = function (file, pairs, dry) {
  var S = SDE.File.Store; try { S.clear(file); } catch (e) {}          // 캐시 말고 서버에서 새로 읽기
  var d = S.get(file); if (!d || d.content == null) return file + ': open fail';
  var c = d.content;
  for (var [a, b] of pairs) {
    var n = c.split(a).length - 1;
    if (n !== 1) return file + ': match count ' + n + ' for ' + a.slice(0, 80);
    c = c.replace(a, () => b);
  }
  if (dry) return file + ': ok (dry)';
  d.content = c; d.isEditing = false;
  return file + ': saved ' + S.set(file, d, true);                    // → /exec/admin/editor/fileSave
};
// 1) __patch('/layout/basic/layout.html', pairs, true)  ← 먼저 dry 로 전부 ok 인지 확인
// 2) __patch('/layout/basic/layout.html', pairs)        ← 저장
```

- 읽기 : `POST /exec/admin/editor/fileOpen?skin_no=1&file=/경로` → `content` 는 `rawurlencode` 되어 있음 (`SDE.File.Store.get` 이 풀어 준다)
- 정규식·백슬래시가 든 코드는 `String.raw\`…\`` 로 넘겨야 깨지지 않는다
- JS 를 바꾸면 **`layout.html` 의 `?v=` 숫자를 꼭 올린다** (안 올리면 브라우저가 옛 파일을 쓴다)
- 올린 뒤 확인 : 쇼핑몰 페이지에서 `[...document.scripts].map(s=>s.src).find(s=>/inter-cms\.js/.test(s))` 가 새 버전인지

### 0-1b. 카페24 보안 확인 (요청이 몰리면)

쇼핑몰 화면(게시판 글쓰기 등)에 짧은 시간 요청을 많이 보내면 카페24가 **「안전한 이용을 위해 간단한 확인이 필요해요」** 페이지(`veritas-hub.cafe24.com/challenge`)로 막는다.
- 자동으로 통과하려 하지 말고, 사람이 브라우저에서 직접 확인을 마친 뒤 다시 한다
- 관리자 화면(`/disp/admin/…`, 스마트디자인 편집기)은 이때도 동작했다
- 여러 건을 처리할 때는 건마다 2~3초 쉬고, 확인용 `fetch` 를 반복하지 않는다

### 0-2. 서버본과 로컬본의 차이

카페24가 저장할 때 `/SkinImg/inter/` 를 `https://ecimg.cafe24img.com/pg…/<몰>/inter/` 로 **바꿔서 저장**한다.
그래서 이미지 경로가 들어간 줄은 로컬 문자열로 찾으면 0번 일치한다 → dry 결과를 보고 서버 문자열로 바꿔 넣는다.

### 0-3. 브라우저 기억(localStorage) 키

| 키 | 내용 |
|---|---|
| `inter-cms-v2-<게시판>-<페이지키>` | 게시판 글 기억. 페이지키 : 메인 `/`, 세일 `list27`, **목록·검색·게시판은 모두 `sub`** (이번에 합침) |
| `inter-cms-draft` | [고치기] 로 넘기는 초안 |
| `inter-cms-kakao` | 카카오톡 채널 주소 |
| `inter-topbanner-hide` | 최상단 띠배너 닫은 시각(자정까지) |

편집 창에서 **저장하면 `inter-cms-v*` 기억이 모두 지워진다** → 저장 직후 새로고침은 게시판을 새로 읽는다.

## 1. 서브 페이지 상단 배너 — 고치기 전 글자·사진이 먼저 보임

**증상** : 목록·검색·게시판 맨 위 큰 배너(`inter/submenu-hero.html`)를 편집 모드에서 바꿨는데, 새로고침하면 옛 글자·사진이 보였다가 바뀐다. 모든 서브 페이지 공통.

**원인**
1. 서브 페이지에는 가림막(`cms-wait`)이 없었다 (메인·세일만 있었음)
2. `INTER_CMS.ready(fill, 1200)` : 게시판이 1.2초 안에 안 오면 **기본값으로 먼저 그리고**, 나중에 글이 와도 다시 그리지 않았다

**해결 (inter-cms.js)**
```js
// ① 가림 걷기 : 억지로 걷을 때(최대 6초 안전장치) 기다리던 코드도 그때 그린다
function unwait(force) {
  if (force) state.hold = false;
  if (state.hold) return;
  html.classList.remove('cms-wait');
  if (force) { var w = state.waiters; state.waiters = []; w.forEach(function (fn) { try { fn(); } catch (e) {} }); }
}
// ② ready : 게시판을 읽는 중(state.hold)이면 기본값으로 먼저 그리지 않는다
state.waiters.push(run); setTimeout(function () { if (!state.hold) run(); }, wait || 800);
// ③ 목록·검색·게시판도 가림막 대상 + 배너만 가리는 CSS
.cms-wait .inter-menu-hero:not(.is-filled)>img, .cms-wait .inter-menu-hero:not(.is-filled)>div>:not(nav){visibility:hidden}
```

**해결 (submenu-hero.html)** : 새 글이 도착하면 다시 그리고(`document.addEventListener('inter:cms', fill)`), 사진이 바뀌면 `is-ready` 를 떼고 새 사진을 다 받은 뒤 보인다.

**원인** : 분류별 배경색 `data-collection` 을 `fill()` 안에서만 넣어서, 기다리는 동안 기본색 → 분류색으로 바뀌었다.

## 3. 서브 상단 배너 — 너무 늦게 뜸 (일반 방문)

**원인**
1. 기억을 **분류·게시판마다 따로** 저장 → 분류를 옮길 때마다 "첫 방문"이 되어 게시판을 새로 읽음(2~4초)
2. 기억이 있어도 `DOMContentLoaded` 뒤에야 그림

**해결 (inter-cms.js)**
```js
// 목록·검색·게시판(세일 분류 제외)은 기억을 함께 쓴다
var CATE = (location.search.match(/[?&]cate_no=(\d+)/) || location.pathname.match(/^\/category\/[^\/]+\/(\d+)/) || [])[1] || '';
var HERO_PAGE = /^\/(product\/(list|search)\.html|category\/|board\/)/.test(location.pathname) && CATE !== String((SC.sale || {}).categoryNo || 27);
var PAGE_KEY = HERO_PAGE ? 'sub' : /\/product\/list\.html/.test(location.pathname) ? 'list' + CATE : (location.pathname.replace(/\/index\.html$/, '/') || '/');

// api 에 추가 : 배너 코드가 실행되는 순간 기억한 내용을 바로 넣는다
holding: function () { return state.hold; },
applyCachedSection: function (sec) {
  if (!BOARD || state.hold || state.applied) return false;
  var c = lsGet(CACHE_KEY); if (!c || !c.map) return false;
  var post = c.map[sec.getAttribute('data-cms')], ad = ADAPTERS[sec.getAttribute('data-cms-adapter')];
  if (post) { try { var data = parse(post.content, knownLabels(sec)); if (ad) ad.apply(data); else applySection(sec, data); } catch (e) { return false; } }
  return true;
},
```
submenu-hero.html :
```js
var C = window.INTER_CMS;
```

**측정** : 분류 이동 시 글자 0.3초·사진 0.5초 (전 2~4초). 기억 없을 때(첫 방문·저장 직후) 약 2초, 이때도 옛 내용은 안 보임.

## 4. 편집 모드(`?edit=1`)에서 늘 늦게 뜸

**원인** : 편집 모드는 기억을 무시하고(`applyCached` 에서 `EDIT` 이면 return), 항상 `state.hold = true` 로 다 읽을 때까지 가렸다.
**해결** : `applyCached`·`applyCachedSection` 의 `EDIT` 조건 삭제, `state.hold = EDIT || …` 에서 `EDIT ||` 삭제.
최신 글은 뒤에서 다시 읽고(편집 모드는 계속 `reread`), 달라지면 다시 그린다. 저장하면 기억이 지워지므로 저장 직후만 기다린다.

## 6. 이벤트 팝업 — 최대 5장까지

**원인** : 편집 창의 [복사해서 추가]·[삭제] 는 안내문에 「칸을 늘리려면」 이 있을 때만 켜진다. 팝업 초안에는 없었다.
**해결**
- inter-cms.js 팝업 어댑터 `draft` 에 `note: '팝업은 최대 ' + POPUP_MAX + '장까지 … 칸을 늘리려면 …'`, `items: s.slice(0, POPUP_MAX)`, `apply` 에서 `.slice(0, POPUP_MAX)` (`POPUP_MAX = 5`)
- inter-cms-editor.js : 안내문의 `최대 N장` 을 읽어 그 수가 되면 [복사해서 추가] 비활성
- inter-cms-editor.js : **이미 저장된 글**에는 새 안내·칸이 없으므로, 편집 창을 열 때 초안(`inter-cms-draft`)에서 보충한다
```js
if (d && d.html) {
  var fresh = parseDoc(d.html), hasNote = {};
  original.forEach(function (b) { if (b.type === 'note') hasNote[b.text] = 1; });
  var addNotes = fresh.filter(function (b) { return b.type === 'note' && !hasNote[b.text] && /칸을 늘리려면|최대\s*\d+\s*[장칸개]/.test(b.text); });
  if (addNotes.length) original = addNotes.concat(original);
  var isMark = function (b) { return b.type === 'marker'; };
  if (!original.some(isMark) && fresh.some(isMark)) original = original.concat(fresh.slice(fresh.findIndex(isMark)).filter(function (b) { return b.type !== 'note'; }));
}
```

## 7. 카카오톡 상담 버튼 — 편집 모드에서 채널 주소 연결

**사용법** : 편집 모드 막대의 **[💬 카카오톡 상담 연결 · 연결됨/연결 안 됨]** → 화면 안 설정 창 → 저장하면 화면 뒤에서 게시판 글을 저장하고 **「카카오톡 채널(_TsIAE)이 연결되었습니다.」** 알림.
- 설정 창은 **처음 하는 사람 기준**으로 쓴다 : 버튼이 하는 일 한 줄 → 지금 연결 상태 → 1단계 채널 주소 복사(💻 컴퓨터: 관리자센터 › 채널 › 채널 정보 › 채널 URL / 📱 휴대폰: 채널 프로필 › 공유 › URL 복사, 채널이 없으면 [새 채널 만들기], 공개·채팅 켜기) → 2단계 붙여 넣기 → 3단계 [미리 열어 보기] 후 [저장]
- 입력 : 주소 전체(`http://pf.kakao.com/_TsIAE`)든 아이디(`_TsIAE`, `TsIAE`)든 받는다. 입력하는 대로 **「연결될 주소」** 를 보여 준다. 체크박스로 `/chat`(바로 1:1 채팅) 켜고 끄기
- 오픈채팅(`open.kakao.com`)·형식이 틀린 값은 쉬운 말로 안내한다. 연결된 상태면 **[연결 해지]** 버튼(확인 창 → 빈 값 저장)
- **여는 곳 두 군데** : 편집 막대의 [💬 카카오톡 상담 연결] + **오른쪽 아래 노란 카카오톡 버튼 자체**(편집 모드에서는 채널로 가지 않고 설정 창을 연다, 버튼 옆에 "✏️ 눌러서 연결 설정" 표시). 사람들은 노란 버튼부터 누르므로 꼭 둘 다 연결할 것
- **펼쳐 보는 자세한 설명(`<details>`)** : 카카오톡 채널이 뭔가요? · 채널이 아직 없어요 — 새로 만들기 · 꼭 켜 둘 설정 두 가지(채널 공개·1:1 채팅) · 잘 안 될 때(찾을 수 없는 채널 / 채팅칸이 없음 / 휴대폰에서 앱이 열림 / 예전 곳으로 감 / 채널 바꾸기·해지 / 보안 확인)
- 저장은 9장의 `silentSave` 를 쓴다 (새 창 없음)

- inter-cms.js : `kakao` 어댑터 (라벨 `카카오톡 채널 주소`) → `SC.floating.kakao` + `localStorage['inter-cms-kakao']` + 버튼 href
- 편집 [고치기] 버튼은 떠 있는 작은 버튼 대신 **편집 막대**에 단다 : `paint()` 에서 `data-cms-bar` 가 있으면 막대로
- layout.html 플로팅 스크립트 :
  - 화면 관리 영역이 있는 페이지면 카카오 버튼에 `data-cms="카카오톡 상담 버튼" data-cms-adapter="kakao" data-cms-page="모든 페이지" data-cms-bar` 를 붙인다
  - 없는 페이지(상품 상세 등)에서 주소를 아직 모르면, **누를 때** `INTER_CMS.fetchField('카카오톡 상담 버튼','카카오톡 채널 주소')` 로 읽어 연다 (먼저 `window.open('about:blank')` → 팝업 차단 방지)

## 9. 섹션 순서 저장 — 새 창 없이 알림 하나로

**증상** : [순서 저장하기] → 새 창이 열리고 거기서 저장된 뒤 돌아와야 했다.
**해결 (inter-cms.js `silentSave(name, draft, done)` + `saveOrder`)** : 보이지 않는 iframe 에 글쓰기/수정 화면을 열고, 편집기의 자동 저장(`autosave: true` 초안)이 끝나 **iframe 이 write/modify 화면을 벗어나면 성공** → `alert('섹션 순서가 변경되었습니다.')`.
`silentSave` 는 카카오톡 연결(7장)도 같이 쓴다. 한 번에 하나만 저장한다(`saving`).
- **iframe 이 다른 주소(카페24 보안 확인 `*.cafe24.com/challenge`)로 넘어가면 실패로 본다** — 주소를 못 읽으면(`path` 빈 값) `finish(false,'blocked')` → "카페24 보안 확인이 필요해 저장하지 못했어요…" 안내. 이걸 안 넣으면 보안 확인 페이지를 "저장 완료"로 착각한다
- iframe 은 `display:none` 이 아니라 화면 밖 + `opacity:0` (편집기가 뜨게)
- iframe 안 `alert`·`confirm` 은 막는다. 25초 안에 안 끝나면 실패 알림
- 처음 쓴 글이면 저장 뒤 `load([name])` 로 글 번호를 받아 두어 다음에는 수정한다
- 측정 : 9~11초

## 10. 탭 제목 중복 (`다이닝 · 소품 - 다이닝 · 소품 - inter902`)

**원인** : 카페24 SEO 제목 형식 "상위분류 - 분류 - 쇼핑몰". 대분류는 상위분류 = 자기 자신.
**해결 (layout.html `<head>`)** : 연달아 같은 부분을 한 번만. 카페24가 `<title>` 을 스크립트보다 **뒤에** 넣으므로 `DOMContentLoaded` 에서도 한 번 더.
```html
<script>try{(function(){function fix(){var p=document.title.split(' - '),o=[];p.forEach(function(s){if(o[o.length-1]!==s)o.push(s)});if(o.length<p.length)document.title=o.join(' - ')}fix();document.addEventListener('DOMContentLoaded',fix)})()}catch(e){}</script>
```
**검색엔진용 원래 제목도 고쳤다** : 관리자 › 쇼핑몰 설정 › 기본 설정 › 검색엔진 최적화(SEO) (`/disp/admin/shop1/seo/main`) › SEO 태그 변수 활용 › **주요 페이지 SEO 태그 설정 › 상품분류 설정** 의 메타태그 Title
`[CATE_NAME1] - [CURRENT_CATE_NAME] - [MALL_NAME]` → **`[CURRENT_CATE_NAME] - [MALL_NAME]`** 으로 바꾸고 [저장하기].
(입력칸이 React 라서 값만 넣으면 저장되지 않는다 — 네이티브 setter 로 넣고 `input` 이벤트를 보낸 뒤 버튼을 누른다. 스킨 스크립트는 하위 분류 등 다른 경우를 위해 그대로 둔다)

## 14. 확인용 도구 — 배너가 언제 보이는지 재기

페이지를 iframe 으로 열어 30ms 마다 상태를 적는다. "고치기 전 내용이 보이는 순간"이 있는지 바로 보인다.
```js
async function rec(url, ms) {
  var f = document.createElement('iframe'); f.style.cssText = 'width:1200px;height:800px;position:fixed;left:-3000px'; f.src = url; document.body.appendChild(f);
  var log = [], t0 = performance.now();
  await new Promise(res => { var iv = setInterval(() => { try {
    var d = f.contentDocument, h = d && d.querySelector('.inter-menu-hero'); if (h) { var w = f.contentWindow;
      log.push([Math.round(performance.now() - t0), 'wait:' + d.documentElement.classList.contains('cms-wait'),
        'bg:' + w.getComputedStyle(h).backgroundColor, 'text:' + w.getComputedStyle(h.querySelector('h1')).visibility,
        'img:' + h.classList.contains('is-ready'), h.querySelector('h1').textContent.slice(0, 14)].join(' ')); }
  } catch (e) {} if (performance.now() - t0 > ms) { clearInterval(iv); res(); } }, 30); });
  f.remove(); return log.filter((x, i) => i === 0 || x.split(' ').slice(1).join() !== log[i - 1].split(' ').slice(1).join());
}
```
